# Акаунти та бекенд єКапітал

Вхід використовує WebAuthn: підпис ключем доступу, перевірка користувача, origin та RP ID, одноразові запити. Face ID / Touch ID визначає пристрій, біометрія серверу не передається. Email-відновлення не реалізоване: додайте запасний ключ або використовуйте синхронізований менеджер ключів. Для додавання ключа та видалення потрібен вхід за останні 10 хвилин.

## Активація

Потрібна PostgreSQL та змінні середовища:

- `DATABASE_URL`: приватне підключення до PostgreSQL.
- `DATA_ENCRYPTION_KEY`: 32 випадкові байти у hex (64 символи); зберігати окремо разом із резервною копією. Втрата ключа означає втрату можливості прочитати профілі.
- `SITE_URL`: точний публічний HTTPS origin; його hostname є RP ID. Після зміни домену старі ключі можуть не працювати на новому домені.
- `ADMIN_USER_IDS`: UUID конкретних власників адмінки через кому, тільки на сервері. Перший користувач не отримує адмінські права автоматично.
- `TRUST_RAILWAY_PROXY=true`: лише за гарантованого доступу через Railway proxy; використовується X-Real-IP.
- `GEOIP_ENABLED=true`: необов’язковий запит IPWhois, тільки після окремої згоди користувача на аналітику та географію. Максимум 500 запитів на добу на весь сервіс, один запит на користувача за 24 години.

Приватна схема створюється транзакційно, усі таблиці мають RLS без публічних політик. Серверне підключення повинно мати право створювати власну схему. Секрети не передаються клієнту. Без бази і ключа входи вимкнені, гостьові плани працюють локально.

## Дані та швидкодія

Профілі шифруються AES-256-GCM з прив’язкою до UUID. Це серверне шифрування, а не наскрізне: ключ є на сервері. Cookie сесії HttpOnly / Secure / SameSite, у базі зберігається лише хеш токена. Термін сесії 30 днів. JSON API захищено перевіркою origin, лімітами обсягу й частоти.

Локальні профілі розділені за UUID. Перенесення гостьових даних виконується явно. Синхронізація після паузи 1,5 секунди надсилає лише змінені секції; ревізії захищають від перезапису іншого пристрою. Читання підтримує ETag / 304. Відновлення зв’язку повторює невдале збереження. При конфлікті потрібно явно вибрати серверну версію. На новому запуску без інтернету підтвердити серверну сесію неможливо; локальні акаунтні дані зберігаються, доступні після входу.

## Аналітика та приватність

За замовчуванням аналітика вимкнена. Події містять лише дозволений тип функції та категорію пристрою, без сум, вмісту полів чи фінансового профілю. UUID події запобігає повторному запису. Географія приблизна, отримана за IP; IP передається IPWhois тільки після згоди. Відкликання згоди видаляє відповідні дані. Видалення акаунта видаляє ключі, сесії, профіль, події й географію каскадно.

Події очищуються після 90 днів, сирий зашифрований IP — після 7 днів, аудит — після 365 днів. `scripts/start.mjs` запускає очищення при старті та щогодини незалежно від відвідувань, поки сервіс працює; також очищення є в API. Збої бази відкладають очищення до наступної спроби. Резервні копії бази потребують окремого графіка та політики видалення у провайдера.

Адмінка має загальну кількість акаунтів, нові за 7 днів, активні за 1/30 днів, використання функцій і географію тих, хто погодився. Метрики не представляють усіх гостей. Активність — вхід або дозволена подія, не час на екрані. Фінансові профілі адмінка не показує.

## Ринки

Метали: облікові ціни НБУ та публічні ціни продажу/викупу ПриватБанку (І категорія), перевірка кожні 6 годин, запасний перевірений знімок не старший 7 днів. Ціна банку задана за грам, покупка — цілими зливками. Наявність, індивідуальні податки, зберігання не підтверджуються цим потоком.

Акції/ETF: інформація та перевірка ліцензій; потік торгових котировок не підключений. Forex/CFD: пояснення плеча, без сигналів та торгівлі. Це обмеження показане в інтерфейсі.

## Перевірки

Unit-тести виконують SQL на PostgreSQL-сумісному PGlite, перевіряють шифрування, RLS, ревізії, згоду та ліміти. Окремий GitHub workflow `accounts.yml` запускає справжній PostgreSQL 17 та Chromium з віртуальним WebAuthn-ключем: реєстрація, підписаний вхід, профіль, вихід, заборона доступу до адмінки, конфлікти ревізій та CSRF. Тестовий пароль і ключ у workflow є виключно одноразовими тестовими даними.
